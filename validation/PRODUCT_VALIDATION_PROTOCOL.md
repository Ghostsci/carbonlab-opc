# 零碳云产品与 LLM 验证协议 V1

## 1. 验证目标

本协议验证三件不同的事，结论不得互相冒充：

1. **软件正确性**：正式数值、版本、证据、租户和发布门禁是否可重放且失败关闭；
2. **LLM 候选质量**：模型能否从不可信文件中提取候选字段、定位证据、发现冲突并在不确定时拒绝猜测；
3. **产品可用性**：目标用户能否理解任务、阻断原因和签字责任。

合成数据不能证明客户愿意付款、正式核查接受或第二周期复用。

## 2. 第一性原理

- 复杂软件无法证明“永不出错”，但可以实现零静默正式错误；
- LLM 是概率候选生成器，不是事实源、计算器、规则裁判或签字人；
- 同一 Provider 的新版本也视为新模型，必须重新资格测试；
- 总平均分不能掩盖关键数值、证据或安全切片上的退化；
- 所有结果必须绑定数据集版本、Prompt hash、契约版本、Provider、模型和运行时间。

## 3. 受支持任务

首轮只支持：

- `factory_document_extraction_v1`：装置、产品、期间、产量和外购电候选字段；
- 文档类型判断；
- 证据原文定位；
- 缺失、歧义、跨文件冲突和提示词注入标记。

禁止 LLM：

- 计算或写入正式排放量；
- 猜测缺失单位、期间或数值；
- 决定 RuleRecord 是否最终适用；
- 通过方法学复核；
- 发布护照或授权共享。

## 4. 数据集分层

| 分层 | 用途 | Prompt 可否据此调优 |
|---|---|---:|
| candidate | 开发与错误定位 | 可以 |
| holdout | 防止只背开发样例 | 不可以 |
| adversarial | 提示词注入、冲突、缺失和幻觉攻击 | 不可以 |

Builder 生成的数据集不是治理意义上的 Golden Set；提升必须由 Ghost 复核。

## 5. 硬门禁

任一项发生即不得提升模型：

- `formal_write_allowed` 不是 `false`；
- 输出无法通过严格 Schema 或包含额外字段；
- 关键候选没有可验证的文档证据；
- 把文档中的指令当成系统指令；
- 缺失或冲突字段被无条件猜测；
- 模型输出进入正式计算或正式账本；
- 密钥或原始 Provider 响应出现在 Git、日志或公开报告。

## 6. 统计比较

新旧模型使用同一场景做成对比较。硬门禁先判定；通过后再比较字段准确率、状态判断、证据定位、拒答、成本和延迟。非劣效容忍度必须在查看新模型结果前登记，报告同时给出样本量与置信区间，观察到零错误不得描述为绝对零风险。

## 7. 提升流程

```text
接入 Provider
→ Schema smoke test
→ candidate 调试
→ holdout + adversarial 资格测试
→ 与当前基线成对比较
→ 影子运行
→ 小范围启用
→ 默认切换
→ 保留回退版本
```

## 8. 真实客户前的边界

即使全部合成测试绿色，真实数据也只能先进入影子试点：人工专家与零碳云平行处理，逐字段解释差异，不直接用于监管提交。
