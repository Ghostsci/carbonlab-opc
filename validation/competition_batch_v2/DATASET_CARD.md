# Competition Batch V2：50 行明细工作簿说明

## 1. 这次增加了什么

本数据集包含 **12 个 XLSX 工作簿**，每个工作簿对应一个虚构设施的一个月度账期，并包含：

- `账单摘要`：1 条月度账单汇总；
- `50条用电明细`：50 条计量点/班次明细；
- `数据说明`：数据性质、勾稽关系、公开背景和禁止用途。

合计为 **600 条用电明细记录**。这里扩充的是 50 行业务记录，而不是人为增加到 50 个字段。真实台账通常是字段数量稳定、记录数量增加；强行扩到 50 列反而不符合业务结构。

## 2. 真实性边界

本数据集是**结构真实、数值自洽的合成数据**，不是实际企业数据，也不是从真实客户账单脱敏得到的：

- 主体名称、户号、计量点、读数、电价和金额均为虚构；
- 每条明细满足“结束读数－起始读数＝用电量”；
- 每个工作簿的 50 条明细合计与月度摘要完全一致；
- 月度数量级用于工程压力测试，不代表某座真实工厂的统计分布；
- 排放计算继续使用 `0.5 kgCO2e/kWh` 的 DEMO ONLY 合成因子；
- 不得用于申报、核查、报价、交易或真实业务决策。

公开背景仅用于字段和数量级常识校验：

- 国家能源局《2026年1-7月份全社会用电量同比增长4.7%》：https://www.nea.gov.cn/20260821/f227e3fb9f05422285e354f4c27aec07/c.html
- 国家电网公开代理购电工商业用户电价表示例：https://www.95598.cn/omg-static/omg-static/99302261906123669376800423273245.pdf

没有复制上述资料中的真实用户数据，也没有将示例地区电价冒充为本项目客户电价。

## 3. 为什么仍保留一条“账单摘要”

当前产品的正式证据模型是“一份月度证据文件对应一个账期活动”。50 条明细用于证明摘要如何形成；系统正式写入的是经过人工确认的月度汇总，而不是把 50 条计量点数据误当成 50 张独立账单。

这种结构既能测试大表读取、证据检索和汇总一致性，也不会破坏现有审计边界。

## 4. 使用方法

1. 解压数据包；
2. 在“数字化员工工作台”逐个上传 `positive/` 下的 XLSX 文件；
3. 核对系统识别出的账期、用电量和工厂；
4. 依次完成 A-03 质检、H-01 企业事实确认、H-02 因子确认和 R-01 计算；
5. 打开原工作簿，可在第二个工作表检查 50 条明细和合计。

前端当前仍是逐文件上传，不是一次选择 12 个文件的批量上传器。

## 5. 重建方式

工作簿由 `scripts/generate_competition_workbooks_v2.mjs` 生成；权威期望值见 `manifest.json`。
