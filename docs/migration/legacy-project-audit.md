# 旧项目审查报告

## 1. 审查结论

旧项目包含一个功能面较宽的“零碳云”平台，除本次赛事所需的文件接入、AI 提取、人工确认、确定性计算、证据链和工厂碳数据护照外，还包含碳市场、绿色金融、供应商、核查工作台、ERP、减排、AgentOps 等大量模块。

本次不复制完整旧仓库，而以“能支撑复赛最小闭环”为边界执行干净迁移。旧项目保持只读，未修改其分支、文件或远程配置。

## 5. 功能分类

### A. 必须迁移

- 文件上传、哈希、类型和处理状态；
- 文件分类与 AI 候选字段提取；
- 字段级证据位置和原文；
- 人工确认、修改、拒绝及留痕；
- Decimal 精确数值、单位和 basis 校验；
- 规则引用、结果计算、回执和重放；
- 工厂/装置账户、护照快照、冻结、发布、追溯和授权共享；
- Candidate、Holdout、Adversarial、Usability 数据集生成与模型一致性验证工具；
- 与上述能力直接相关的后端和前端测试。

### B. 迁移后需要适配

- `backend/main.py`：缩小为最小路由集合，避免暴露旧平台无关 API；
- Alembic 环境：仅注册新仓库保留的模型，同时保留必要的既有迁移链；
- 前端 `App.tsx` 和 `Layout.tsx`：移除无关页面和菜单；
- 配置：移除本地绝对路径、真实凭据和开发机专属默认值；
- Docker Compose：保留本地开发用途并明确非生产边界；
- 测试：调整到新仓库的最小应用入口和迁移后的目录。

### C. 可以迁移但非必要

- Redis/Celery 异步任务能力；
- 监控栈；
- 离线部署包；
- 全平台通用组件和国际化资源。

本轮默认不迁移，除非核心闭包验证表明确显示为运行依赖。

### D. 明确不迁移

- 碳交易、绿证撮合、绿色金融、收益分成；
- 自动监管申报和第三方法定核查替代功能；
- ERP、减排、碳市场、资产、价格、供应商门户等旧业务页面和 API；
- 旧商业计划、营销材料、PPT、截图、私人笔记；
- `competition/` 临时材料；
- 构建产物、缓存、日志、上传文件、数据库文件；
- 旧仓库 Git 历史。

### E. 待人工决定

- 赛事结束后是否重新引入 Redis/Celery 和生产监控；
- 是否公开源代码或更换许可证；
- GitHub 仓库的最终可见性、组织归属和协作者权限；
- 真实企业数据的接入方式和数据处理协议。

## 7. 状态边界检查

目标状态为：

`received → candidate → evidence_checked → confirmed/rejected → calculated → frozen → published`

现有代码具备候选、确认、计算、冻结与发布的主要结构，但迁移后必须重新验证以下不变量：

1. `candidate` 不得直接进入 `calculated` 或 `published`；
2. 只有人类操作可以把候选改为 `confirmed`；
3. 发布前必须校验证据、单位、规则、权限和重放结果；
4. AI 输出不得直接写入正式账本；
5. 任何发布版本必须能够从冻结输入重放。

未能用迁移后测试证明的约束，将在交接矩阵中标记“待赛事平台后续开发/验证”，不得伪造为完成。

## 8. 风险审查

### 8.1 敏感信息

旧仓库文本扫描发现若干敏感模式命中（包括 `sk-`、`PASSWORD=`、`SECRET=`、`TOKEN=`、`API_KEY=`、`DATABASE_URL=`）。命中可能来自示例、测试 canary 或历史文档，但新仓库不会直接复制这些文件；所有迁移文件将在提交前再次逐项扫描。

### 8.2 本地路径

旧仓库有多处 `/Users/Ghost/...` 绝对路径，主要位于历史报告和交接材料。新仓库运行时代码和文档不得依赖旧路径；迁移报告中记录来源路径属于审计事实，是唯一允许保留的绝对路径类型。

### 8.3 平台和外部服务

- DeepSeek/OpenAI-compatible 模型需要用户自行提供环境变量；不得提交 Key；
- OCR、对象存储或外部数据库如未配置，应明确降级行为；
- GitHub App 当前未授权任何仓库，无法由本任务直接创建或推送远程仓库；
- 真实企业文件、个人信息和法定报告不进入仓库。

### 8.4 数据库迁移

护照依赖既有租户、企业、文档、活动、账本、CBAM 和规则记录表。迁移时保留必要的 Alembic 链，但应用只暴露最小业务路由。必须用 PostgreSQL 实际执行迁移后才能声明“迁移通过”。

### 8.5 测试与产品边界

- 旧项目历史测试数量不是本次结论；只报告新仓库实际运行结果；
- UI 存在不等于后端闭环完成；
- 合成数据通过不等于真实企业验证；
- 模型一致性通过不等于模型可直接写正式账本；
- 本项目是数据准备、核算和可信护照工具，不是法定核查机构。

## 9. 审计决定

不存在需要扩大迁移范围的关键歧义。按以下边界继续：

1. 最小前端路由；
2. 后端核心依赖闭包；
3. 必要数据库迁移链；
4. 相关测试、合成数据工具和技术文档；
5. 不迁移旧平台的其他业务表面与历史材料。
