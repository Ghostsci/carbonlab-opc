# CarbonLab 赛事最小演示运行手册

> 版本日期：2026-08-21  
> 演示边界：仅使用合成数据，非监管申报、非第三方核查、非真实客户交付。

## 1. 本轮只证明一件事

CarbonLab 能把一份工厂电费数据，经过“AI 提取候选—人工核对—系统锁定确认对象—确定性计算—护照归集”，变成一条有源文件、有确认指纹、可继续复核的数据记录。

本轮不证明系统已经可以替代审计机构，也不演示采购、交易、全行业因子库或自动发布。

## 2. 五分钟演示路径

1. 登录本地演示租户，进入“数据收件箱”。
2. 点击“下载合成演示账单”，再上传该 CSV。
3. 查看 AI 识别出的报告期、用电量和所属装置；人工核对后点击“锁定候选并确认写入”。
4. 页面显示本次确认指纹和活动数据结果；点击“进入护照归集”。
5. 护照页自动高亮刚确认的排放结果。人工点击“100% 归集到本工序”，随后可登记产量并生成 SEE。

## 3. 为什么要先锁定再写入

AI 只负责提出候选，不能直接写正式账本。系统在人工点击确认时，对“操作者、租户、源文件哈希、文档类型和全部字段”生成一个短时有效的服务端签名。正式写入前会重新比对：只要字段、文件或操作者发生变化，写入就会被拒绝。

这不是为了增加操作步骤，而是为了明确回答审计类产品最重要的问题：**人当时确认的，是否就是系统最终写入的那一组数据。**

## 4. 演示验收点

| 验收点 | 可见证据 |
|---|---|
| AI 输出不直接入账 | 上传后状态为待确认，必须人工点击确认 |
| 确认对象不可偷换 | 修改签名后的任一字段，后端返回冲突并拒绝写入 |
| 数量符合基本业务约束 | 零值、负值、二进制浮点被服务层与数据库边界拒绝 |
| 来源可追溯 | 活动记录绑定源文件 ID、内容哈希和候选确认指纹 |
| 工作流连续 | 写入后携带结果 ID 跳转护照，并高亮待归集记录 |
| 高风险动作仍由人决定 | 归集、冻结、复核、发布均不会由 AI 自动执行 |

## 6. 失败时如何解释

- 没有可计算排放结果：演示数据库缺少匹配因子，先运行种子脚本。
- 护照没有高亮记录：确认结果尚未计算，或 URL 没有携带 `emission_result_id`。
- 候选快照失效：超过 15 分钟或确认前字段发生变化；重新点击确认即可生成新快照。
- 数据库迁移阻断：先审计历史零值、负值或非法期间记录，不能绕过迁移前置检查。
- 数据库有文件记录但预览 404：确认容器设置 `LOCAL_STORAGE_DIR=/app/uploads`，且后端挂载同一个持久卷。

## 7. 赛事表达建议

一句话介绍：**我们不是让 AI 替企业“算一个数字”，而是让 AI 帮人整理证据和提出候选，再由人确认、确定性代码计算，最终形成可复核的工厂碳数据护照。**
