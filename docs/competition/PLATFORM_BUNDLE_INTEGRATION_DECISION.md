# 比赛平台交付包集成决策

## 决策

比赛平台生成的 `competition/minimum-demo-delivery` 分支予以保留并单独推送，用作过程留痕和实验材料；不直接合并到 `main`。

主产品采用选择性集成：吸收“候选数据必须先锁定、确认后才允许正式写入”的机制，复用现有上传、正式活动账本和工厂碳数据护照，不引入第二套平行护照模型。

## 原因

1. 平台分支证明了候选护照机制的方向，但其 M3 仍是独立服务和测试，未接入真实 API 与前端。
2. 原产品已经具备上传、活动账本、排放结果、装置护照、归集、SEE、冻结、复核、发布与授权共享链路；整体替换会制造重复模型和迁移风险。
3. 审计发现平台候选对象存在可变字典与负数字符串解析问题，因此只能“修复后吸收”，不能原样上线。

## 本轮产品切口

`合成电费 CSV → AI 字段候选 → 人工核对 → 签名锁定 → 正式活动记录 → 排放结果 → 护照人工归集`

这条路径足以验证 AI 原生人机协同结构，同时把不可逆动作留给确定性代码和人工授权。

## 明确未纳入

- 平台交付包中的平行 Candidate Passport 数据模型；
- 自动发布、自动申报或“AI 已完成审计”的表述；
- 全量行业规则、真实客户数据、真实核查结论；
- 与最小演示无关的交易、绿证采购和大而全运营模块。
