# CarbonLab 最小演示交付报告

## 1. 交付结论

本轮没有扩建“大而全”的零碳平台，而是完成并实测了一条可上手演示的最小闭环：

`合成电费文件 → AI 字段候选 → 人工核对 → 服务端签名锁定 → 正式活动账本 → 确定性排放结果 → 工厂碳数据护照人工归集`

比赛平台原分支保留为独立过程证据，不直接覆盖主产品；主产品只吸收了经修复的候选确认机制。

## 2. 本轮完成内容

### 人机协同边界

- AI/文档识别只提出可编辑字段候选；
- 人点击确认后，系统对操作者、租户、企业、文件哈希、文档类型和完整字段集生成 15 分钟有效的签名快照；
- 正式写入前重新核验签名，字段被偷换、跨用户、跨租户、跨文件或过期均拒绝；
- 归集、冻结、复核、发布仍需人工动作，不因 AI 输出自动执行。

### 数据与数据库完整性

- 服务层拒绝零值和负活动数量；
- 模型元数据与 033 迁移增加数量大于零、开始时间早于结束时间的数据库约束；
- 迁移前自动检查历史非法数据，发现问题即阻断而不是静默修正；
- 活动记录的派生来源增加候选确认指纹，确认对象可追溯。

### 产品闭环

- 数据收件箱新增“锁定候选并确认写入”；
- 成功后显示确认指纹和排放结果；
- 携带 `emission_result_id` 跳转护照；
- 护照页将刚确认的结果置顶、高亮，并明确提示“归集不会自动发布”；
- 提供可直接下载的合成演示 CSV；
- 演示种子的默认因子严格限制在 `DEMO_ONLY` 区域，不匹配任何真实地区活动。

### 证据文件持久化

- 修复 Docker 挂载 `/app/uploads`、代码却写入 `/app/backend/.uploads` 的路径错位；
- 新增 `LOCAL_STORAGE_DIR`，Compose 明确设置为持久卷路径；
- 容器重建后源文件仍可预览和下载。

## 4. 已验证的攻击

1. 用合法签名确认后再修改任一字段：返回冲突，不写 ActivityData。
2. 将负数量作为候选字段签名后确认：服务层拒绝。
3. 绕过服务直接把已存在 ActivityData 更新为负值：数据库约束拒绝。
4. 大整数 `9007199254740993`：精确保留，不经过 JavaScript/Python 二进制浮点污染。
5. 客户端提交二进制浮点：拒绝。
6. 跨租户、缺失源文件及错误文件哈希：原有门禁保持通过。

## 5. 尚未宣称完成

- 本轮不是法定 CBAM 核查或第三方审计产品验收；
- 合成因子、合成企业、合成规则和合成接收方不能用于真实申报；
- 尚未用真实工厂资料完成用户试点；
- 尚未形成生产级因子选择与审批界面；真实环境不能依赖演示因子；
- OCR 对扫描图片型 PDF 的支持仍不属于本轮最小闭环；
- 集成分支在 PR 评审通过前不应合并到 `main`。
